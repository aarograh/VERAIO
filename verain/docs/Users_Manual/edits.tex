\section{Edits} \label{chap:edits}

A wide range of output edits can be enabled by the user.  This chapter will briefly describe the possible edits that can be enabled by the user along with several other useful input options related to controlling the edits.

\subsection{The \texttt{edit} Input}

\subsubsection{Enabling Edits through the \texttt{edit} Input}

Most output edits are enabled using the \texttt{edit} input in the \texttt{[STATE]} block.  The \texttt{edit} input should only be used once per state block, with a list of all the edits the user wishes to enable.  Once edits are enabled in a state block, they will remain enabled in all subsequent states.  If a user wants to disable them later, then including the keyword \texttt{none} will disable all previously enabled edits.  There is a list of default edits which cannot be disabled; those will be described in Section \ref{sec:default-edits}.  If \texttt{none} and other valid edits appear next to each other in the same \texttt{edit} input, then \texttt{none} will disable all previously enabled edits first, then the other edits listed alongside \texttt{none} will be enabled.

As an example, one regression test uses the following \texttt{[STATE]} blocks:
\begin{verbatim}
[STATE]
  power    0.0
  tinlet   565 K
  tfuel    565 K
  modden   0.743         ! g/cc
  boron    1300          ! ppm
  sym      full          ! full symmetry
  feedback off
  thexp    off
[STATE] edit pin_flux
[STATE] power 0.0
[STATE] edit none
[STATE] edit pin_isotopes_U-235
[STATE] edit pin_isotopes_U-238
[STATE] edit none pin_isotopes_U-235 pin_isotopes_U-238
[STATE] power 0.0
[STATE] edit pin_flux
[STATE] power 0.0
[STATE] edit none
[STATE] edit pin_powers
[STATE] edit pin_isotopes_U-235
\end{verbatim}
This produces 13 states, with the following edits enabled for each state:
\begin{enumerate}[noitemsep]
    \item default edits
    \item default edits + \texttt{pin\_flux}
    \item default edits + \texttt{pin\_flux}
    \item default edits
    \item default edits + \texttt{pin\_isotopes\_U-235}
    \item default edits + \texttt{pin\_isotopes\_U-235} + \texttt{pin\_isotopes\_U-238}
    \item default edits + \texttt{pin\_isotopes\_U-235} + \texttt{pin\_isotopes\_U-238}
    \item default edits + \texttt{pin\_isotopes\_U-235} + \texttt{pin\_isotopes\_U-238}
    \item default edits + \texttt{pin\_isotopes\_U-235} + \texttt{pin\_isotopes\_U-238} + \texttt{pin\_flux}
    \item default edits + \texttt{pin\_isotopes\_U-235} + \texttt{pin\_isotopes\_U-238} + \texttt{pin\_flux}
    \item default edits
    \item default edits (because \texttt{pin\_powers} is a default edit)
    \item default edits + \texttt{pin\_isotopes\_U-235}
\end{enumerate}
This illustrates enabling and disabling various edits separately and simultaneously.

There are a few other edits which are not enabled in the \texttt{[STATE]} block by the \texttt{edit} input, but rather through other code-specific options.  These are discussed separate in Section \ref{sec:other-hdf5-edits}.

\subsubsection{Edit Groups}

Another useful option is the \texttt{edit\_group} input in the \texttt{[EDITS]} block.  This allows the user to create a group of edits that can be enabled or disabled together.  The name of the group is then used in the \texttt{edit} input of the \texttt{[STATE]} block just like any of the other edits.  When the group name appears in the \texttt{edit} input, each component of the group is enabled as if it were explicitly named.  The \texttt{none} input will disable groups the same way it disables individual edits.

\subsubsection{Point Edit Locations}

One specific category of edits is a point edit, which is used to return a particular mesh or solution value at one point in the mesh.  To use point edits, the \texttt{points} input must be specified in the \texttt{[EDITS]} block.  This input takes a set of four values.  Each set contains the coordinate type and 3 values.  The coordinate type can be either \texttt{cart} or \texttt{rtheta}.  If \texttt{cart}, the 3 values are the $x$, $y$, and $z$ coordinates in the mesh; if \texttt{rtheta}, the 3 values are the radius, angle (degrees counter-clockwise from the positive x axis), and $z$ coordinate.  In both cases, the origin is the center of the reactor.  There is no limit on the number of points specified in the \texttt{points} input, and each one can use a different coordinate type if desired.  The actual point edits supported by the codes will be described in Section \ref{sec:point-edits}.

\subsubsection{Supported Edits}

There is a wide range of supported edits.  They can be grouped according to the level of resolution of the edit.  Doing so results in the following categories: \texttt{fsr}, \texttt{intrapin}, \texttt{pin}, \texttt{channel}, \texttt{core}, and \texttt{point}.  Any edit that can be enabled from input will fall into one of these categories; the category is always used as a prefix for the name of the edit in the input (e.g., \texttt{pin\_powers} is part of the \texttt{pin} category).

Grouping edits by resolution category is useful because it is guaranteed that all edits of a particular category will have the same shape.  The following terms will be used to describe the shape of the edits:
\begin{itemize}[noitemsep]
    \item \texttt{nFuelReg} the number of burnup regions in the model
    \item \texttt{nxpin} the number of pins across an assembly in the x direction
    \item \texttt{nypin} the number of pins across an assembly in the y direction
    \item \texttt{nz} the number of axial levels in the active fuel region
    \item \texttt{nasy} the number of assemblies in the model
    \item \texttt{nxchan} the number of channels across an assembly (usually equal to \texttt{nxpin} + 1)
    \item \texttt{nychan} the number of channels across an assembly (usually equal to \texttt{nypin} + 1)
\end{itemize}
The following sections will provide the shape of the edit category and a list of supported edits in that category.  Additional information about the output formats may be found in the VERAOut specifications \cite{godfrey2014}.  Note that the shape and units will be provided in the tables as a reference, but all \ac{hdf5} datasets also have \ac{hdf5} attributes containing units, descriptions, and the name of the code that produced it.

Several edits used indexes, which refer to the following:
\begin{itemize}[noitemsep]
    \item \texttt{<group>} the neutron energy group
    \item \texttt{<gamma group>} the gamma energy group
    \item \texttt{<isotope>} the isotope using the element name and mass number separate by a hyphen (e.g., \texttt{U-235}, \texttt{B-10}, etc.)
    \item \texttt{<delayed group>} the delayed neutron precursor group
    \item \texttt{<reaction>} the reaction type: \texttt{abs}, \texttt{fis}, or \texttt{nufis}
\end{itemize}

\paragraph{FSR Edits}\label{sec:fsr-edits}

The \texttt{fsr} edits are unique compared to the rest of the categories because they are not placed in the VERAOut (\ac{hdf5}) file.  Instead, they are used for visualization.  The name of the edit is placed in the \texttt{[STATE]} block's \texttt{edit} input like the others, but the \texttt{vis\_edits} input in the \texttt{[MPACT]} block must also be set to either \texttt{fsr} to obtain VTK edits or \texttt{fsrvtu} to obtain VTU edits.  If the \texttt{vis\_edits} input is not set, then the \texttt{fsr} edits will not do anything.  The resulting VTK or VTU files can be opened in a visualization program, such as VisIt or ParaView, to view the fine mesh solution data produced as an \texttt{fsr} edit. \paragraph{Assembly Edits}\label{sec:assembly-edits}

The \texttt{assembly} datasets have the shape \texttt{(nasy, nz)}.  Currently the only \texttt{assembly} datasets that are generated by \ac{vera} are not controlled through the \texttt{edit} input.  They are discussed in section \ref{sec:bwr-edits}.

\paragraph{Core Edits}\label{sec:core-edits}

At this time, the only available \texttt{core} edit is \texttt{avg\_flux}, which is a default edit and is therefore always enabled.  The units of \texttt{avg\_flux} are neutrons/cm$^2$*s.  Its shape is a 1D array with length equal to the number of neutron energy groups.

\subsubsection{MPACT Inputs}

\paragraph{\acrshort{sth} Edits}

For feedback calculations that set \texttt{coupling\_method simplified} in the \texttt{[MPACT]} block, the list of feedback edits from Section \ref{sec:feedback-edits} will not be generated.  Instead, the \ac{sth} solver will be used, which generates a smaller set of outputs.  Specifically, for \ac{bwr} calculations, a \texttt{radial\_assembly\_flow\_dist} dataset will be produced, which has the flow in kg/s for each assembly in the core.

If the \texttt{[BRANCH]} block is used to generate the nodal cross sections, then a group called \texttt{BRANCHES} is placed at the root of the VERAOut file, and it contains directories for each unique branch case.  Each \texttt{STATE\_\#\#\#\#} group will then have an integer \texttt{active\_branch} that identifies which entry in \texttt{BRANCHES} that state point corresponds to; a value of 0 indicates nominal conditions.  Additional detail on brnach calculations is given in Section \ref{chap:branches}.

\paragraph{Nodal Cross Section Edits}

Nodal cross section edits can be enabled using the \texttt{nodal\_edits} input described in Section \ref{sec:mpactinputs}.  When enabled, each \texttt{STATE\_\#\#\#\#} group in the VERAOut file will contain the following new groups:
\begin{enumerate}[noitemsep]
    \item \texttt{CORE\_XS}, which contains a few core-homogenized datasets;
    \item \texttt{ASSEMBLY\_XS}, which contains a full set of nodal cross section data for every axial level and assembly in the model, including reflector regions; and
    \item \texttt{NODAL\_XS}, which is the same as \texttt{ASSEMBLY\_XS}, but provides 4 nodes of data for each axial level and assembly.
\end{enumerate}
These data can be used directly to drive the 3D nodal solver in MPACT, or they can be post-processed to drive external nodal codes.

\paragraph{Critical Buckling Calculations}

If the \texttt{crit\_buckling} input from Section \ref{sec:mpactinputs} is used, then several datasets are produced: \texttt{critical\_buckling}, \texttt{critical\_buckling\_method}, \texttt{critical\_keff}, and \texttt{critical\_spectrum}.  These can be used for postprocessing and analysis; if nodal cross section edits are enabled, then the critical spectrum will be used in the generation of nodal data as well.

\paragraph{Reaction Rate Edits}

The \texttt{rr\_edits} and \texttt{rr\_edits\_opt} inputs, described in Section \ref{sec:mpactinputs}, can be used to enabled detailed reaction rate edits.  These edits provide reaction rates as a function of isotope and reaction type.  The data will be stored in \texttt{STATE\_\#\#\#\#/reaction\_rates} and \texttt{STATE\_\#\#\#\#/reaction\_rate\_details}.
