\section{VERARun}  \label{chap:verarun}

This chapter describes running cases with the VERARun script.
VERARun is the driver script that runs the input processor and corresponding VERA component codes.
VERARun also submits the job to the parallel job queue.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{Running a Case}

VERARun is run by specifying {\tt verarun} on the command line, followed by the name of the input file.
Additional command line options are shown subsequently.
\begin{Verbatim}[fontsize=\small]

--> verarun <input file>

\end{Verbatim}

For example, if your input deck is called \texttt{2a.inp,} you would enter
\begin{Verbatim}[fontsize=\small]

--> verarun 2a

\end{Verbatim}

To see what versions of VERA are available, use the -l option:
\begin{Verbatim}[fontsize=\small]

--> verarun -l
Available VERA versions (newest to oldest, * for default):
  VERA_4.1
  VERA_4.2 *

\end{Verbatim}

To use a different VERA version, use the -v option:
\begin{Verbatim}[fontsize=\small]

--> verarun -v VERA_4.2 file.inp

\end{Verbatim}

To use a development version of VERA (not usually recommended), use the --devs option:
\begin{Verbatim}[fontsize=\small]

--> verarun --devs -v VERA_4.3RC2 file.inp

\end{Verbatim}

To see additional VERARun command line options, just execute VERARun with no other command line input.
To see detailed help and customizable environment variables use the -h option.
Doing so will return the following:

\begin{Verbatim}[fontsize=\small]

usage: verarun [--devs] [-x] [--schema] [-e email_addr] [-h] [-c config_file]
               [-N job_name] [-l] [-n nprocs] [-O] [-M] [--ppn cpus_per_node]
               [-m mem_per_process] [-p project] [-q queue] [-s subdir]
               [-d vera_install_dir] [-v vera_version] [--verbose] [-W]
               [-w job_id] [-t walltime] [--chain] [--debug] [--hostname host]
               [-r {overwrite,readwrite}]
               [--vera-installs-dir vera_installs_dir]
               [input_path [input_path ...]]

Creates and optionally submits machine-specific VERA jobs.

positional arguments:
  input_path            path to VERA input (.inp) or XML (.xml) files

optional arguments:
  --devs, --allow-devs  override VERA_PROD_VERSIONS and allow development VERA
                        versions, implies -l
  -x, --dry-run         dry run only, create but don't execute the PBS script
  --schema              schema from react2xml.pl
  -e email_addr, --email-addrs email_addr
                        comma-delimited list of email addresses to notify of
                        job completion, defaults to ${USER}@$(hostname)
  -h, --help            print detailed help
  -c config_file, --host-config-file config_file
                        override host configuration file, supercedes
                        --hostname and --vera-installs-dir
  -N job_name, --job-name job_name
                        name for the PBS job
  -l, --list-vera-versions
                        list available VERA versions
  -n nprocs, --np nprocs, --nprocs nprocs, --num-procs nprocs
                        total number of processors need for the MPACT run
                        (mpiexec -np param), defaults to value computed from
                        input
  -O, --output-job-name
                        print the job id to stdout
  -M, --messages        print messages as process is run
  --ppn cpus_per_node, --pnode cpus_per_node

                        calculated
  -m mem_per_process, --pmem mem_per_process, --proc-memory mem_per_process

                        to undefined
  -p project, --project project
                        optional project or account to specify for the job,
                        overriding any default, where a value of "none" omits

  -q queue, --partition queue, --queue queue

  -s subdir, --subdir subdir

VERARun uses machine-specific characteristics to determine batch system
directives applied to a job script template.  Additional template parameters,
such as which models and utilities to execute, are determined from the VERA
input file (.inp).  Configurations are provided for machines commonly in the
VERA program.  In order to port \texttt{verarun} to another environment it will be
necessary to create a machine spec file.

\subsection{Execution}

There are two verarun usage modes:
\begin{itemize}
    \item If the \texttt{-l} command-line argument is specified, available VERA installations
  are listed.  If \texttt{--verbose} is also specified, required files that are
  missing in each \texttt{vera\_installs\_dir} subdir are listed.
  \item If one or more VERA input files (.inp) are specified, a job script is created
  based on each input file.  Note pre-processed VERA input XML (.xml) may be
  also be specified.  If no file extension is given \texttt{.inp} is assumed.
\end{itemize}

By default the current directory will be used for all processing.
Alternatively, you may specify that a subdirectory in the current directory be
created and used as the working directory via the \texttt{-s} command-line argument.
Specifying a directory value of \texttt{.} will tell \texttt{verarun} to create a subdirectory with
name \texttt{\{input\_name\}\_\{datetime\}}, where \texttt{\{input\_name\}} is the name of the input file
without the \texttt{.inp} or \texttt{.xml} extension, and \texttt{\{datetime\}} is the ISO 8601 extended
date format: \texttt{yyyy-mm-ddThh:mm:ss}.

A job script named with a \texttt{.pbs} extension is created in the working directory.
If the \texttt{-x} argument is not specified, the job is also submitted.  Output from
the job will be in a file with extension \texttt{.stdout} in the working directory.

\subsection{Machine Specifications}

Machine specifications are stored in JSON (\texttt{.json}) files under the \texttt{verarun}
Python package installation directory:

\begin{Verbatim}
../lib/python2.7/site-packages/verarun-<version>-py2.7.egg/verarun/config/
\end{Verbatim}

It is also possible to specify a configuration file with the \texttt{-c} command-line
argument.

\subsection{Job Script Template}

The Job template is a Bash script named \texttt{vera.pbs} stored under the \texttt{verarun}
installation directory:

\begin{Verbatim}
  ../lib/python2.7/site-packages/verarun-<version>-py2.7.egg/verarun/job/
\end{Verbatim}

Parameter values are substituted by name for curly-brace expressions in the
template (.e.g., \texttt{\{job\_name\}}).

\subsection{Environment Variables}

There are environment variables which can be set to override behavior.
\begin{itemize}
\item \texttt{PBS\_EMAIL}: sets the email address to be used for PBS notifications,
  overridden by the \texttt{-e}  parameter (or \texttt{\-\-email-addrs}).
\item \texttt{PBS\_PROJECT}: sets the project for the job, overriding any default set in
  the host configuration but overridden by the \texttt{-p} (or \texttt{--project}) parameter.
\item \texttt{VERA\_BUILDS}: path to the directory containing VERA builds or installs.  May also be specified as
  \texttt{VERA\_BUILDS\_DIR} or \texttt{VERA\_INSTALLS\_DIR}.
  Overrides the \texttt{\$(hostname).json} file but  is overridden by the
  \texttt{--vera-installs-dir} parameter.
\item \texttt{VERA\_BUILDS\_DIR}: alternative name for \texttt{VERA\_BUILDS}, where \texttt{VERA\_BUILDS} has
  priority.
\item \texttt{VERA\_DEFAULT\_VERSION}: names the default version of VERA to use, overriding
  what is specified in the host configuration file but overridden by the \texttt{-v}
  (or \texttt{--vera-version}) parameter.
\item \texttt{VERA\_INSTALLS\_DIR}: alternative name for \texttt{VERA\_BUILDS} or \texttt{VERA\_BUILDS\_DIR},
  priority order being \texttt{VERA\_BUILDS}, \texttt{VERA\_BUILDS\_DIR}, then \texttt{VERA\_INSTALLS\_DIR}
\item \texttt{VERA\_PROD\_VERSIONS}: comma-delimited list of allowed production VERA versions.
\item \texttt{VERA\_QSUB}: custom \texttt{qsub} command to execute for hosts running Torque or
  PBS Pro.
\item \texttt{VERA\_SBATCH}: custom \texttt{sbatch} command to execute for hosts running SLURM.
\item \texttt{VERA\_SUMMARY\_EMAIL}:  if set and not blank, the \texttt{case.sum} file is emailed
  to the user when MPACT completes.
\item \texttt{VERARUN\_HOST\_CONFIG\_FILE}: path to a host configuration file to use,
  overriding the distributed \texttt{\$(hostname).json} file but overridden by
  the \texttt{-c} parameter.
\end{itemize}

Note that VERARun will create a \texttt{.pbs} file that can also be modified and submitted manually using \texttt{qsub}.
After job submittal, the job is managed by the typical queueing system commands (\texttt{qdel}, \texttt{qhold}, \texttt{qrls}, etc.).

With VERARun 1.11 and beyond, you can receive emails summarizing your job when it completes successfully.
Depending on the font of your email client, this summary can be more or less readable.
In Outlook, you can force plain text emails to use a certain font (such as Courier New) by going to \texttt{Options -> Mail -> Stationary and Fonts -> Composing and reading plain test messages...}.

To get information on past jobs submitted with VERARun, use the \texttt{verastat} command. This will provide a listing of job ID, date/time, and file location. To get info on a specific job, use
\begin{Verbatim}[fontsize=\small]

--> verastat job_id

\end{Verbatim}

For additional questions or support, please contact \href{vera-support@ornl.gov}{vera-support@ornl.gov}.

\subsection{VERARun Output}

Upon completion of a VERA job, several output files might be created depending on the code options used.
Some typical outputs include the following:
\begin{itemize}
\item VERAIn XML file. This file is written upon successful completion of VERAIn.
\item VERA HDF5 output file. This is a binary file with results that can be visualized in VERAView or be postprocessed with user utility codes.
\item MPACT output file. This file is written upon the successful completion of MPACT (if applicable).
\item MPACT log file. This file is written upon the successful completion of MPACT (if applicable).
\item MPACT summary file. This file is written upon the successful completion of MPACT (if applicable).
\item Standard output file. This file is a log of all output written to the standard output.
\item Standard error file. This file is a log of all output written to the standard error file.
\end{itemize}

\subsection{Input Errors}

If the {\tt verarun} command does not work, the user should make sure that it is in the path.
The user might need to consult with the system administrator for the correct path.

The next step when looking for an error is to look at the standard error file.
If the job ran successfully, the size of this file will be zero.

If there were any errors in VERAIn, the errors will be written to the standard error file.
Common errors from the input processor include the following:
\begin{enumerate}
\item Invalid keywords
\item Invalid map sizes
\item Invalid input options
\end{enumerate}

If the input processor works correctly, an error still might occur in one of the VERA component codes.
The user should look at the error message and consult the user manual for the component code.
